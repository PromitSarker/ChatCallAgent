# RAG System Analysis: Why it Sometimes Fails to Fetch Data

After a thorough analysis of the RAG implementation in `agent/rag.py` and `agent/nodes.py`, the intermittent retrieval failures are primarily caused by a silent failure in the Vector Embeddings model, which forces the system to rely entirely on a less capable keyword-based fallback.

Here is a breakdown of what is causing the issue:

### 1. Invalid Gemini Embedding Model
In `rag.py`, the dense retriever (Vector Search) is initialized using an incorrect model name:
```python
query_embeddings = GoogleGenerativeAIEmbeddings(
    model="models/gemini-embedding-001", # <--- ISSUE HERE
    ...
)
```
**Impact:** `models/gemini-embedding-001` is not a valid Google GenAI model (the correct names are `models/embedding-001` or `models/text-embedding-004`). 
Because of this, `query_embeddings.embed_query(query)` throws an API error every single time it is called.

### 2. Silent Failure & Over-reliance on BM25 Fallback
The RAG search function has a `try-except` block for the embedding generation:
```python
for attempt in range(3):
    try:
        embedded_query = query_embeddings.embed_query(query)
        # ...
    except Exception as e:
        print(f"[RAG Search] Embeddings attempt {attempt + 1} failed: {e}")
        time.sleep(2 ** attempt)
```
**Impact:** When the invalid model throws an error, the code catches it, retries, and ultimately leaves `vector_results` empty. The code then silently falls back to the Sparse Retriever (`BM25Retriever`). The system completely loses its semantic search capabilities without breaking the app, making the issue hard to spot.

### 3. BM25 Cross-Lingual & Synonym Limitations
Because the Vector Search is permanently offline, all searches are being handled by BM25. BM25 is a keyword-based algorithm that tokenizes strings and relies on exact word matches.
**Impact:** 
- **When it works:** If the LLM generates an English query like `"Short Code SMS"` and the document contains exactly those words, BM25 successfully fetches the data.
- **When it fails:** The agent supports Bengali queries. If the query generated by the LLM is in Bengali (e.g., `"শর্ট কোড এসএমএস এর দাম কত?"`), or if it uses synonyms, BM25 finds zero overlapping words with the English documents. It returns empty results, and RAG fails to fetch data.

### Minor/Secondary Issue: Reciprocal Rank Fusion (RRF) Bug
In the RRF logic, `fused_scores` uses `doc.page_content` as a dictionary key:
```python
fused_scores[doc.page_content] = {"doc": doc, "score": 0}
```
If two distinct documents (with different metadata) happen to have the exact same text content, the dictionary key will overwrite the first one. While not the main cause of the missing data, it can cause data loss during the reranking phase if there are identical text chunks.

### Summary
The system "sometimes" works because BM25 occasionally gets lucky with exact keyword matches. It "sometimes" fails because any semantic, conversational, or cross-lingual queries are failing to match in BM25, and the primary Vector Search (which would have solved this) is offline due to a typo in the embedding model name. Fixing the model name to `models/text-embedding-004` or `models/embedding-001` will restore the semantic search and resolve the issue.
